# 药安心 MVP v2 复审报告

**复审日期：**2026-09-11
**复审范围：**`index.html`、`demo.html`、长辈端与子女端首页、`app.js`、`conversation.js`、`rules.js`、`demo-bridge.js`、`styles.css`，以及[《药安心 MVP 文档 v2》](../../../药安心_MVP文档_v2.md)。
**复审性质：**实现前的只读复审。本报告写入后，原型源码仍未修改。

## 1. 结论

现有原型的核心家庭协同链路基本可演示：账号和长辈档案切换、共享本地数据、本人打卡、子女权限限制、延后／补记／更正、三系统舞台、模拟通知、BMI 和两种字号均有实现证据。当前证据目录中 13 个已完成结果文件共包含 **635 项通过的浏览器断言**，另有 **37 组纯规则检查**通过。

`step01.browser.js` 未完成，因为一次点击目标被自动聚焦弹窗遮挡；它不计入上述通过总数，也不据此判定产品缺陷。其余结果文件的具体统计见第 4 节。

但本次人工复现发现两个需要先处理的功能缺陷：计划解析会把明确的否定语义解析成错误剂量；在加药助手中输入“早餐提醒时间改为09:00”不会更新当前未保存计划。两者都会影响用户最终核对和保存结果，不能仅归为视觉问题。

另外有三类界面和演示准备问题：长辈首页首屏把当前打卡操作推到较下方；子女看板的日历位于页面很后面，与用户要求的“日历在上方、上半部分不放看板统计面板”不符；计划表的餐前／餐后控件纵向堆叠，未达到文档要求的单行左右分段布局。右下角助手目前仍使用聊天气泡图标，用户明确要求将**长辈首页**入口改成话筒图标；子女端同步替换是后续的一致性建议。子女日历顺序／压缩和长辈话筒图标属于本轮新增待实施要求。

## 3. 子女首页请求的解释边界

用户的新增要求可概括为：子女首页上半部分不要被 dashboard 统计面板占据，日历应放到更靠前的位置，原本位于下方的日历需要压缩以便快速浏览。这里是对当前会话要求的中文转述，不是未经核实的逐字引语。按当前界面结构，dashboard 最合理的对应物是上方三项统计块及其周围的看板摘要，不是删除“首页看板”页面名称，也不是删除“今日用药”“未按时打卡”或身体数据。

当前 DOM 顺序已经证明统计块和今日用药先于日历；因此后续实现应调整模块顺序和密度，而不是把必需数据从产品中删掉。MVP v2 §2.4 允许在视觉评审中调整三个模块顺序，D14 也把看板顺序列为部分待定，所以本次用户要求足以作为后续实现决策。验收时应同时确认：日历位于首屏较上位置、统计信息仍可访问、今日用药与提醒仍保留、切换档案后所有模块使用同一对象。助手话筒图标的明确目标是长辈首页；子女端是否同步替换属于一致性实现建议。

## 4. 已确认通过的范围

- **账号与权限：**张阿姨／小李可以切换；子女可以查看已授权长辈，但没有“已服用／未服用／本次无需服用”、更正和延后操作。共享数据在切换和刷新后保持一致。
- **业务规则：**四自然时段、左闭右开边界、每任务一次延后、保护期、跨午夜、本人三种声明、5 秒撤销、历史更正和严格星星资格已有规则与浏览器证据。
- **计划表基础功能：**药品名、数值用量、自定义单位、四时段、默认提醒、时间范围校验、开始日期／周期、统一核对和醒目必填错误层均可见。这里的通过不覆盖上表提出的餐时横向布局问题。

## 5. 尚未验证或不应宣称的范围

- 没有真人 VoiceOver、NVDA 或 TalkBack 操作；辅助功能树检查不能替代读屏软件测试。
- 没有真实 iOS／HarmonyOS／Android 安装包、后台／锁屏进程、系统通知授权、双设备云同步或真实推送回执测试。
- 没有真实麦克风、ASR、模型接口或音频上传；“按住说话”仍是明确标注的模拟示例输入。
- 没有进行真实医疗安全、处方核验、药物相互作用或临床决策验证。
- `demo.html` 浏览器会话在控制台出现一次 `favicon.ico` 404；`index.html` 已声明 `data:,` favicon。这是低优先级静态资源噪声，不是本次发现的 JavaScript 业务错误，后续可为 `demo.html` 补齐或显式禁用请求。

## 7. 建议实施顺序

1. 修复否定／改口解析，并补精确回归测试。
2. 修复计划上下文中的提醒时间修改和草稿双向同步。
3. 调整餐时横向分段布局，随后处理长辈首屏与子女日历顺序／紧凑度。
4. 将长辈首页助手替换为话筒图标（子女端可同步保持一致），补 fresh-state N1 演示准备路径。
5. 在三系统、标准／大字号、320/360/390/1280px 视口重新运行功能和布局检查，再更新验收记录。
